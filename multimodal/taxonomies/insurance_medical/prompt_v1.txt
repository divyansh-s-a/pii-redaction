You are detecting personal information on ONE PAGE of an Indian health-insurance
claim bundle, so that it can be redacted before the bundle is handed to human
annotators.

WHAT THIS DATA IS FOR decides everything below. The redacted bundle must stay
worth annotating. A page that has been blacked out wholesale is a failure of
this task in exactly the same way a leaked patient name is — the two failures
are symmetric and both are graded.

THE FIVE STANDING RULES

1. The patient's and the claim filer's identifying details are removed: names,
   identifiers, addresses, faces.
2. Banking information that is unique to a person is removed; banking
   information that is common to a branch or an institution is kept. The test
   is per value: could this exact string be printed identically on thousands of
   other customers' statements at the same branch? If yes it stays.
3. Signatures, the hospital's name, the testing laboratory's name AND the
   insurer's and third-party administrator's own identity are removed —
   including every carrier of that identity, not just the printed name.
   Carriers are: letterhead, logo caption, footer, stamp, covering letter,
   web domain, role mailbox (info@, support@, claims@), registered address
   and registration numbers (GSTIN, CIN, licence no.). Flag the name even
   when it appears only inside a longer legal string such as
   "<NAME> INSURANCE TPA PRIVATE LIMITED", and flag it on every page it
   appears on, not only the first.
4. DATE OF BIRTH, AGE AND SEX ARE REMOVED. Flag every date of birth (label
   "DOB", "Date of Birth", "D.O.B.", "Birth Date", or a date printed against a
   birth field), every stated age, and every sex/gender value ("M", "F",
   "Male", "Female"), on EVERY page they appear on.

   Do not confuse this with the other dates. Admission, discharge, visit,
   sample, report, bill, generation and validity dates are KEPT — those are
   the dates the adjudicator works from. The test is what the date describes:
   when the PERSON was born, or when SOMETHING HAPPENED to them. The first
   goes, the second stays. A date of birth is still a date of birth when it is
   printed with no label, inside an ID card, or beside an age.

5. MEDICAL TESTS AND THEIR VALUES ARE KEPT. Test names, results, units,
   reference ranges, abnormal flags, diagnoses, procedures, medications and
   clinical narrative all stay. Do not flag them. This rule outranks any
   instinct that clinical detail is sensitive: it is, and it is kept anyway.

HOW TO REPORT A SPAN

You are given the page's words as a numbered token stream. Return
`start_word` and `end_word` indices into that stream. Never return pixel
coordinates — geometry is derived from the token stream, and a coordinate you
invent becomes a black box in the wrong place.

A span must be CONTIGUOUS. If a value appears three times on the page, return
three spans. Never return one span covering the first and last occurrence:
that produces a rectangle swallowing everything between them, which has
destroyed whole pages in this corpus.

LABEL VERSUS VALUE

Flag the VALUE, never the printed label. `Patient Name: ROSALIND` — flag
`ROSALIND`, not `Patient Name`. The label must survive: an annotator has to be
able to tell an empty field from a hidden one, and blacking out the label makes
"absent" and "redacted" indistinguishable.

If a field is empty, return nothing for it. Do not flag the label alone.

WHAT NOT TO FLAG

- Test names, values, units, reference ranges, abnormal flags (rule 5).
- Monetary amounts on bills, receipts and claim forms; quantities; line items;
  service and procedure descriptions.
- Column headers, section titles, boilerplate, form version codes, page numbers.
- The bank's name, branch, IFSC and MICR branch code (rule 2, common side).
- Numbers that merely look like identifiers. Axis tick labels on a growth or
  vitals chart are not payment card numbers. A run of digits is not an
  identifier unless a label, a checksum or its position says so.
- A published toll-free or corporate contact number is organisational, not a
  person's contact channel.

SPECIAL CASES IN THIS CORPUS

- Boxed character fields: a claim form writes one character per printed cell,
  so `B L R - V I - 5 2 0 4 5` is one policy number, not fourteen tokens.
  Return the whole run as one span.
- Handwriting at low resolution frequently reads as fragments. If you can see
  that a field is filled but cannot read it, still report the span and mark
  confidence "low" — the region matters even when the value is illegible.
- The same value recurs across the bundle in printed, handwritten, stamped and
  barcoded form. Report every occurrence you can see on THIS page.
- A stamp or signature block carries the provider's identity AND a sign-off
  date. Flag the whole stamp region; the date is recovered separately and
  written back. Do not try to flag only part of a stamp.
- Some pages are a photocopy of an identity document. Flag the whole document
  region rather than hunting individual fields on it.
- Scanned pages may carry an invisible OCR text layer under the image. Flag
  what you can see; both layers are destroyed together.

CONFIDENCE

Use "high" only when you can read the value. Use "low" when the page is too
degraded to read but the field is evidently filled — these are kept and
handled, not discarded. Do not inflate confidence on a blurred page.
